# Data safety 核对参考

本文件是对当前源码的核对记录，不替代最终 Android 构建审计。

## 当前代码观察

- 未发现开发者服务端、账号、广告、分析或崩溃上报 SDK。
- 处理内容：property details, notes, photographs and participant signatures。
- 核心处理在设备完成；用户主动分享时由系统和所选接收应用处理内容。
- 私有 GitHub 仓库不参与应用用户数据处理。

## 建议回答及前提

| 问题 | 当前建议 | 提交前核对 |
|---|---|---|
| 收集用户数据？ | No，前提是没有数据从设备发送到开发者/第三方 SDK | 检查最终依赖、网络请求及日志 SDK |
| 分享用户数据？ | 按 Google 的用户主动分享例外核对，可能无需申报为 sharing | 限于用户明确选择接收方的系统分享；没有后台发送 |
| 传输加密 | 没有收集数据时不凭空承诺网络加密 | 按 Console 实际显示和最终实现填写 |
| 删除机制 | 当前无云端账号；不要填写虚假的云账号删除 URL | 检查本机删除、系统卸载和系统备份行为 |
| 隐私政策 | 必须公开可访问，应用内也应提供入口 | 发布本包英文草稿并补 Android/备份/联系方式说明 |

只有设备本地处理不等同于开发者收集数据。用户主动发送给第三方的例外需按官方定义核对。Android 系统备份可能复制本机数据，应决定是否关闭或在策略中准确说明。

Rental Report 的相机/照片由 image_picker 使用系统能力；不要为了截图方便申请宽泛相册访问权限。两个计算器不应需要相机、位置、通讯录或广泛存储权限。

若加入 AdMob、Firebase Analytics、Crashlytics、云同步、登录或支付 SDK，重新检查本表和隐私政策。

[官方定义与填写指引](https://support.google.com/googleplay/android-developer/answer/10787469?hl=en)
